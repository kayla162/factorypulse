# Power Automate Desktop 與 Python：各適合什麼情境

同一段工作「讀宇碩的 Excel 出貨單 → 寫進資料庫 → 檢查單價、數量、料號」，分別用 Power Automate Desktop（PAD）
和 FactoryPulse 的 Python 程式做一次。PAD 版本在 [pad/](../pad/README.md)。

> 下表的「設計比較」是依兩個實作的內容整理；「實測」欄要在 PAD 實際跑過後填入，目前**尚未實測**。

## 設計比較

| 面向 | Power Automate Desktop | Python（FactoryPulse） |
|---|---|---|
| 上手門檻 | 拖拉動作，業務單位可自己改 | 要會寫程式 |
| 找資料的方式 | 固定儲存格（B4、第 8 列起）；供應商改版面就要改流程 | 找「料號」表頭、挑對工作表；版面移動不受影響 |
| 一家換三家供應商 | 每家一條流程，或用很多 If 分支 | 共用表格抽取，新供應商多半只要補欄名同義詞 |
| 掃描檔、OCR、LLM | 有內建 OCR 與 AI Builder，但多半要額外授權，調校空間小 | RapidOCR 地端執行、可校正歪斜與簡繁轉換；LLM 輸出可程式驗證 |
| 寫進資料庫 | SQL 動作**不能用參數**，只能把值拼進字串，每個欄位要自己跳脫 `'` 防止 SQL 隱碼攻擊 | SQLAlchemy 參數化查詢，自動處理 |
| 異常規則 | 寫在另一份 SQL 查詢（[pad/檢查.sql](../pad/檢查.sql)） | 寫在程式裡，有自動化測試與 CI |
| 版本控制與審查 | 流程存在雲端／本機，很難看出兩版差在哪 | Git 逐行比對、Pull Request 審查、CI 自動測試 |
| 執行方式 | 需要 Windows 桌面與登入的使用者；無人值守排程需 Premium 授權 | Docker 在伺服器上跑，n8n 排程，不需要有人登入 |
| 操作舊系統畫面 | **強項**：可點按鈕、填欄位、讀視窗，適合沒有 API 的舊 ERP／MES 用戶端 | 弱項：沒有 API 就很難接 |
| 費用 | Windows 11 內建，有人值守免費 | 開源套件免費；需要伺服器與維護人力 |

## 結論：怎麼搭配

- **用 PAD**：資料只在舊系統的畫面上、沒有 API；流程簡單、格式固定；由業務單位自己維護的小型自動化。
  例如每天早上從舊 ERP 用戶端把「未交採購單報表」匯出成 Excel，放到共用資料夾。
- **用 Python**：格式多變、需要驗算與比對規則、需要 OCR 或 LLM、需要測試與版本控制、要在伺服器上無人值守執行。
- **兩者接力**：PAD 負責「把舊系統的資料拿出來」，FactoryPulse 負責「讀懂、檢查、通知」。
  對有二十年歷史、系統新舊並存的製造業，這比全部換成同一種工具務實。
