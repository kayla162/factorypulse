# FactoryPulse 交接文件

給接手維護的工程師。使用者操作請看 [操作說明](操作說明.pdf)，驗收項目請看 [測試清單](測試清單.md)。

## 1. 系統在做什麼

| 流程 | 觸發 | 輸入 | 輸出 |
|---|---|---|---|
| 進料文件 | n8n 每 5 分鐘 → `POST /api/poll` | Mailpit（正式環境換成公司信箱）的未讀信 | 寫入 `doc_*`、`erp_goods_receipt`、`erp_incoming_inspection`；異常通知 |
| 產線良率 | n8n 上班時間每小時 → `POST /api/mes/run` | `FP_MES_DROP` 資料夾的 MES／AOI 匯出 CSV | 寫入 `mes_*`、`mart_*`；管制圖失控時回查批號並通知 |
| 日報 | n8n 平日 17:30 → `POST /api/reports/daily` | 資料庫 | `reports/FactoryPulse日報_YYYYMMDD.xlsx`；LINE 摘要 |
| 錯誤警示 | 任一 n8n 流程失敗 | n8n 錯誤資訊 | LINE 警示 |

## 2. 元件與埠（docker-compose.yml，全部只綁 127.0.0.1）

| 服務 | 埠 | 說明 |
|---|---|---|
| `mssql` | 14330 | SQL Server 2022 Developer（正式環境請改用公司授權的 SQL Server） |
| `mailpit` | 8025（網頁／API）、1025（SMTP） | 測試信箱，只收不寄 |
| `api` | 8000 | FastAPI；`/health` 不需金鑰，其餘要 `X-API-Key` |
| `n8n` | 5678 | 排程；流程定義在 `n8n/workflows/` |

## 3. 程式碼地圖（src/factorypulse/）

| 模組 | 職責 |
|---|---|
| `pipeline.py` | 進料主流程：一封信 → 每個附件一個交易 |
| `parsers/` | `pdf_text.py`（文字層）、`ocr.py`（掃描檔）、`excel.py`、`layout.py`（共用表格抽取與欄名同義詞） |
| `normalize.py` | 數字、日期（含民國）、批號、料號對應 |
| `rules.py` | 驗算與異常規則（不用 LLM） |
| `classify.py`、`llm.py` | 信件分類：規則 → Gemini Tool Calling → 驗證 |
| `etl.py`、`spc.py`、`trace.py`、`mes.py` | 產線：清洗匯入、p 管制圖、批號回查、事件通知 |
| `notify.py` | 通知內容組裝；`api.py` 回傳給 n8n 推送 |
| `report.py`、`stats.py`、`dashboard.py` | Excel 日報、省時統計、儀表板資料 |
| `config.py` | 異常規則表、負責人、AQL、人工時間預設值 |
| `evaluate.py`、`evaluate_mes.py`、`pad_compare.py` | 評測與 PAD 比對 |

## 4. 設定與機密（`.env`，不進版控）

| 變數 | 用途 | 備註 |
|---|---|---|
| `MSSQL_SA_PASSWORD` | 資料庫密碼 | 正式環境不要用 sa，另建只有必要權限的帳號 |
| `FP_DB_URL` | 本機命令列連線字串 | 容器內的 API 由 compose 另外設定 |
| `FP_API_TOKEN` | n8n 與儀表板呼叫 API 的金鑰 | 外洩時換掉並重啟 `api`、`n8n` |
| `GEMINI_API_KEY`、`FP_GEMINI_MODEL` | LLM 信件分類 | 沒設就只用規則，其餘轉人工 |
| `LINE_CHANNEL_ACCESS_TOKEN`、`LINE_TO`、`LINE_API_BASE` | LINE 推送 | 沒設時推到 API 內建的假 LINE（`outbox/line_mock.jsonl`） |
| `FP_OCR=0`、`FP_LLM=0` | 關閉 OCR／LLM | 測試與 CI 用 |

## 5. 日常檢查

```bash
python -m factorypulse status        # 最近 5 次執行與採購單到貨狀況
python -m factorypulse stats         # 自動入帳率、人工介入率、省時
docker compose ps                    # 容器是否健康
docker compose logs api --tail 50
```

- n8n 網頁 → Executions：看每次排程是否成功。
- 資料庫：`ops_run_log`（每次執行）、`etl_reject`（被擋下的 MES／AOI 原始列）、`ops_anomaly`（未結異常）。

## 6. 常見問題排除

| 症狀 | 可能原因 | 處理 |
|---|---|---|
| n8n 回 401 | `FP_API_TOKEN` 不一致 | `.env` 改好後 `docker compose up -d api n8n` |
| n8n 回 409 | 上一批還在跑（OCR 或大量 AOI） | 正常現象，下一輪會補；若持續發生，拉長排程間隔 |
| `/api/poll` 回 502 | 連不到信箱 | 檢查 `mailpit` 容器或正式信箱的帳密、網路 |
| 文件狀態 `failed` | 新格式抓不到單號或明細 | 看 `doc_document.error`；多半是欄名不同，在 `parsers/layout.py` 的 `HEADER_SYNONYMS` 補同義詞，並加測試 |
| 文件狀態 `needs_ocr` | 掃描檔但 OCR 被關掉或沒安裝 | 確認 `FP_OCR` 未設成 0、容器有 rapidocr |
| 大量「料號對不到」 | 新供應商或供應商換料號寫法 | 在 ERP 的 `erp_vendor_part_map` 補對照；確定是打錯的請採購退回供應商 |
| 良率誤報 | 3σ 管制圖本來就有少量誤報，或製程真的改了 | 單日誤報可忽略。中心線目前用該線全部歷史資料估計；製程永久改變（換模具、換 AOI 模型）後，需要讓 `mes.chart_points` 只取改變後的資料，這個功能尚未實作 |
| AOI 檔被整批擋下 | 匯出格式改了（欄名、時間格式） | 看 `etl_reject.rule` 與 `raw`，在 `etl.py` 調整清洗規則 |
| 日報沒產生 | 日報流程失敗或 `reports/` 沒掛載 | n8n Executions 看錯誤；確認 compose 的 `./reports` volume |
| LINE 沒收到 | Token 過期、Bot 不在群組、免費方案額度用完 | 用 LINE Developers 後台確認；n8n 推送節點會回錯誤碼 |

## 7. 常見維護作業

- **新增供應商**：`erp_vendor` 加一筆（含寄件網域）；料號寫法不同就補 `erp_vendor_part_map`；
  收 3～5 份樣本放進新的測試資料夾，跑一次確認解析正確，再補進自動化測試。
- **調整異常規則或負責人**：`config.py` 的 `ANOMALY_RULES`、`OWNERS`、`AQL_LIMIT`。改完跑 `pytest`。
- **更新人工時間基準**：`python -m factorypulse baseline delivery 7.5 --source "2026-12 採購部計時 20 份平均"`。
- **新增產線**：`config.LINE_NAMES` 加線別；MES 匯出的線別寫法由 `etl.normalize_line` 統一。
- **換 AOI 模型**：AOI 匯出檔的 `threshold`、`model_version` 欄位會跟著寫入，不需改程式；但門檻改變後良率基準會移動，
  而中心線目前用全部歷史資料估計（見第 11 節），換模型前要先補「依日期切換基準期」的功能。

## 8. 備份與還原（已實際驗證）

```bash
# 備份（壓縮，約 2 MB）
docker compose exec mssql bash -c '/opt/mssql-tools18/bin/sqlcmd -C -S localhost -U sa -P "$MSSQL_SA_PASSWORD" -Q "BACKUP DATABASE factorypulse TO DISK = N'"'"'/var/opt/mssql/data/factorypulse.bak'"'"' WITH INIT, COMPRESSION"'
docker cp factorypulse-mssql:/var/opt/mssql/data/factorypulse.bak ./backup/

# 還原到另一個名稱先檢查（確認沒問題再換掉正式資料庫）
docker compose exec mssql bash -c '/opt/mssql-tools18/bin/sqlcmd -C -S localhost -U sa -P "$MSSQL_SA_PASSWORD" -Q "RESTORE DATABASE fp_check FROM DISK = N'"'"'/var/opt/mssql/data/factorypulse.bak'"'"' WITH MOVE N'"'"'factorypulse'"'"' TO N'"'"'/var/opt/mssql/data/fp_check.mdf'"'"', MOVE N'"'"'factorypulse_log'"'"' TO N'"'"'/var/opt/mssql/data/fp_check_log.ldf'"'"'"'

# n8n 流程匯出
docker compose exec n8n n8n export:workflow --all --separate --output=/home/node/.n8n/backup/
```

Git Bash 執行 `docker compose exec` 前先 `export MSYS_NO_PATHCONV=1`，否則 `/opt/...` 路徑會被改寫。

## 9. 更新部署

```bash
git pull
docker compose up -d --build api      # 套件層有快取，只改程式碼時很快
python -m factorypulse init-db        # 只會新增缺少的資料表
```

**注意**：`init-db` 不會修改既有資料表的欄位。目前沒有資料庫遷移工具（例如 Alembic），
改欄位時要自己寫 `ALTER TABLE`，或在測試環境用 `init-db --reset` 重建。這是正式上線前要補的項目。

## 10. 測試與評測

```bash
pytest -q                                             # 全部測試；有開 SQL Server 時一併跑 MS SQL
python -m factorypulse eval --strict --no-llm         # 進料：誤報、漏抓、讀錯就失敗
python -m factorypulse eval-mes --strict              # 產線：ETL、偵測、回查
python -m factorypulse pad-compare                    # PAD 跑完後比對
```

GitHub Actions 每次 push 會跑 SQLite 版本的測試與兩個評測。

## 11. 已知限制與待辦

- 測試資料是合成的；正式導入前要收集真實單據建立「困難集」分開計分。
- Gemini 分類、LINE 推送、n8n 錯誤警示、PAD 流程尚未用真實帳號驗證（見測試清單 ⬜ 項目）。
- 人工時間基準是假設值，省時數字要等現場計時。
- 沒有資料庫遷移工具；沒有使用者權限管理（API 只有一把共用金鑰）。
- 文件只處理第一頁；AOI 逐片分數目前是模擬的。
- 管制圖中心線用全部歷史資料估計，還不能指定「製程變更後」的基準期。
